\hypertarget{aurora-serverless-v2}{%
\subsubsection{1. Aurora Serverless v2}}

\emph{(Mã nguồn chi tiết đã được lược bỏ để báo cáo ngắn gọn. Vui lòng
xem trong source code dự án)}

\textbf{Tips:} - Dùng \textbf{ACU = 0.5} minimum cho dev (scale to 0 khi
idle) - Production: \textbf{min=1, max=16} cho HA - Monitor
\texttt{ServerlessDatabaseCapacity} metric để tune - Cân nhắc
\textbf{Provisioned} với \texttt{db.t4g.medium}
(\textasciitilde\$45/tháng) nếu workload ổn định cao

\hypertarget{lambda-right-sizing}{%
\subsubsection{2. Lambda Right-Sizing}}

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\# Dùng AWS Lambda Power Tuning để tìm optimal memory}
\CommentTok{\# https://github.com/aws{-}lambda{-}power{-}tuning/aws{-}lambda{-}power{-}tuning}

\CommentTok{\# Kết quả điển hình:}
\CommentTok{\# {-} Consumer: 512 MB (CPU scales with memory)}
\CommentTok{\# {-} ETL: 1024 MB (cần memory cho pgvector ops + Bedrock)}
\CommentTok{\# {-} RAG API: 1024 MB (embedding + search + LLM)}
\end{Highlighting}
\end{Shaded}

\textbf{Cost vs Performance:} \textbar{} Memory \textbar{} CPU
\textbar{} ETL Duration \textbar{} Cost/Invocation \textbar{}
\textbar--------\textbar-----\textbar--------------\textbar-----------------\textbar{}
\textbar{} 512 MB \textbar{} 0.8 vCPU \textbar{} 180s \textbar{}
\$0.0000018 \textbar{} \textbar{} 1024 MB \textbar{} 1.7 vCPU \textbar{}
90s \textbar{} \$0.0000018 \textbar{} \textbar{} 2048 MB \textbar{} 3.5
vCPU \textbar{} 50s \textbar{} \$0.0000020 \textbar{}

\(\rightarrow\) \textbf{1024 MB là sweet spot} cho ETL (2x nhanh hơn,
same cost)

\subsubsection{6. S3 cho Cold Data

đây trong pgvector.

\hypertarget{rds-proxy-for-high-concurrency}{%
\subsubsection{7. RDS Proxy (For High
Concurrency)}}

\emph{(Mã nguồn chi tiết đã được lược bỏ để báo cáo ngắn gọn. Vui lòng
xem trong source code dự án)}

\textbf{Khi dùng:} \textgreater{} 50 concurrent Lambda connections
\textbf{Cost:} \textasciitilde\$0.015/hr per vCPU =
\textasciitilde\$11/tháng cho db.t4g.medium equivalent \textbf{Lợi ích:}
Connection pooling, reduced cold start, better scalability
