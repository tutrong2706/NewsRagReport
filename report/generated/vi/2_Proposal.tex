\section{News RAG Pipeline trên
AWS}}

\hypertarget{ux111ux1b0ux1eddng-ux1ed1ng-dux1eef-liux1ec7u-serverless-vux1edbi-rag-cho-hux1ecfi-ux111uxe1p-tin-tux1ee9c-thuxf4ng-minh}{%
\subsection{Đường ống dữ liệu Serverless với RAG cho hỏi đáp tin tức
thông
minh}}

\hypertarget{tuxf3m-tux1eaft-ux111iux1ec1u-huxe0nh}{%
\subsubsection{1. Tóm tắt điều
hành}}

News RAG Pipeline là hệ thống xây dựng ứng dụng hỏi đáp tin tức thông
minh, tự động thu thập bài báo từ các trang tin Việt Nam (VnExpress,
Thanh Niên, VietnamNet), xử lý qua Data Warehouse (Star Schema), tạo
vector embedding bằng Amazon Bedrock Titan Embed v2, và cho phép người
dùng đặt câu hỏi bằng ngôn ngữ tự nhiên thông qua kiến trúc RAG
(Retrieval-Augmented Generation) --- hoàn toàn serverless trên AWS. Hệ
thống là minh chứng thực tế về tích hợp dịch vụ serverless AWS với LLM
API (Groq, Gemini) để tạo nền tảng tra cứu thông tin AI.

\hypertarget{tuyuxean-bux1ed1-vux1ea5n-ux111ux1ec1}{%
\subsubsection{2. Tuyên bố vấn
đề}}

\hypertarget{vux1ea5n-ux111ux1ec1-hiux1ec7n-tux1ea1i}{%
\paragraph{Vấn đề hiện
tại}}

Theo dõi tin tức từ nhiều nguồn đòi hỏi đọc và tìm kiếm thủ công qua vô
số bài báo. Không có hệ thống tập trung cho phép người dùng đặt câu hỏi
về tin tức mới nhất và nhận câu trả lời AI có trích dẫn nguồn. Các giải
pháp hiện có như ChatGPT thiếu ngữ cảnh tin tức cập nhật.

\hypertarget{giux1ea3i-phuxe1p}{%
\paragraph{Giải pháp}}

News RAG Pipeline tự động hóa toàn bộ quy trình: (1) Scrapy crawler trên
ECS Fargate thu thập bài báo từ sitemap tin tức, (2) bài viết được đưa
qua SQS vào Aurora PostgreSQL, (3) Lambda ETL xử lý HTML thô thành Star
Schema và tạo vector embedding qua Amazon Bedrock Titan Embed v2, (4)
Lambda RAG API nhận câu hỏi ngôn ngữ tự nhiên, tìm kiếm tương đồng
vector trên pgvector (HNSW index), và sinh câu trả lời dùng Groq
(Qwen3-8B, Llama 3.1) hoặc Gemini 2.0 Flash --- tất cả được điều phối
bởi EventBridge Scheduler.

\hypertarget{lux1ee3i-uxedch-vuxe0-houxe0n-vux1ed1n-ux111ux1ea7u-tux1b0}{%
\paragraph{Lợi ích và hoàn vốn đầu
tư}}

Giải pháp cung cấp nền tảng học tập về kiến trúc serverless AWS, hệ
thống RAG và MLOps. Lợi ích chính: tổng hợp tin tức tự động loại bỏ tìm
kiếm thủ công, hỏi đáp AI có trích dẫn nguồn tiết kiệm thời gian nghiên
cứu, trải nghiệm thực tế với 10+ dịch vụ AWS, và hạ tầng serverless tiết
kiệm chi phí. Chi phí hàng tháng khoảng \$21-26 USD.

\hypertarget{kiux1ebfn-truxfac-giux1ea3i-phuxe1p}{%
\subsubsection{3. Kiến trúc giải
pháp}}

Nền tảng sử dụng kiến trúc serverless AWS với hai giai đoạn pipeline:
(1) Data Pipeline --- EventBridge Scheduler kích hoạt ECS Fargate
crawler hàng ngày lúc 01:00 UTC, đẩy bài viết vào SQS; Lambda Consumer
xử lý messages và insert bài thô vào Aurora PostgreSQL với SHA256 dedup.
(2) ETL + RAG Pipeline --- EventBridge thứ hai lúc 02:00 UTC chạy Lambda
ETL làm sạch HTML, chunk text 500 token, tạo embedding 1024 chiều qua
Bedrock Titan Embed v2, lưu vector vào Aurora pgvector với HNSW index.
Lambda RAG API, phía sau API Gateway, embed câu hỏi người dùng với
Bedrock, tìm kiếm tương đồng trên pgvector, sau đó sinh câu trả lời dùng
Groq/Gemini LLM.

\hypertarget{cuxe1c-dux1ecbch-vux1ee5-aws-sux1eed-dux1ee5ng}{%
\subsubsection{Các dịch vụ AWS sử
dụng}}

\begin{itemize}
\tightlist
\item
  \textbf{Amazon ECS Fargate}: Chạy Scrapy SitemapSpider crawler (0.25
  vCPU, 0.5 GB)
\item
  \textbf{Amazon SQS Standard}: Message queue thay thế Kafka
  (\textasciitilde\$0/tháng)
\item
  \textbf{AWS Lambda} (3 functions): Consumer (SQS \(\rightarrow\)
  Aurora), ETL + Bedrock Embed, RAG API
\item
  \textbf{Amazon Aurora Serverless v2}: PostgreSQL 15.4 với pgvector
  extension
\item
  \textbf{Amazon Bedrock}: Titan Embed Text v2 (1024d) cho vector
  embeddings
\item
  \textbf{Amazon API Gateway}: REST API frontend cho RAG queries
\item
  \textbf{Amazon EventBridge Scheduler}: Cron trigger hàng ngày (01:00,
  02:00 UTC)
\item
  \textbf{Amazon ECR}: Docker image registry cho Fargate tasks
\item
  \textbf{AWS IAM}: Task execution và Lambda roles với least-privilege
  policies
\item
  \textbf{Amazon CloudWatch}: Centralized logging và monitoring (7-day
  retention)
\end{itemize}

\hypertarget{thiux1ebft-kux1ebf-thuxe0nh-phux1ea7n}{%
\subsubsection{Thiết kế thành
phần}}

\begin{itemize}
\tightlist
\item
  \textbf{Crawler (Fargate)}: Scrapy SitemapSpider đọc sitemap\_news.xml
  từ 3 nguồn báo, parse bài viết, đẩy vào SQS. Chạy \textasciitilde30
  phút/ngày.
\item
  \textbf{Queue (SQS)}: Standard queue với DLQ, 14-day retention, 3 lần
  retry.
\item
  \textbf{Consumer (Lambda)}: Triggered bởi SQS, tính SHA256 URL hash
  cho dedup, insert bài thô vào Aurora.
\item
  \textbf{ETL + Embed (Lambda)}: Làm sạch HTML, chunk text (500 tokens,
  50 overlap), gọi Bedrock Titan Embed v2, lưu vector 1024d trong
  pgvector với HNSW index.
\item
  \textbf{RAG API (Lambda + API Gateway)}: Embed câu hỏi qua Bedrock,
  cosine similarity search trên pgvector, sinh câu trả lời qua
  Groq/Gemini có trích dẫn nguồn.
\item
  \textbf{Frontend (Next.js + FastAPI)}: Dashboard với KPI cards, charts
  (Recharts), AI Chat với model selector, Article Explorer, Pipeline
  Monitor.
\end{itemize}

\hypertarget{triux1ec3n-khai-kux1ef9-thuux1eadt}{%
\subsubsection{4. Triển khai kỹ
thuật}}

\hypertarget{cuxe1c-giai-ux111oux1ea1n-triux1ec3n-khai}{%
\paragraph{Các giai đoạn triển
khai}}

Dự án theo 4 giai đoạn: - \textbf{Giai đoạn 1 - Hạ tầng (Tuần 1-2)}:
Terraform cho VPC, Aurora pgvector, ECS Cluster, ECR, Lambda,
EventBridge, IAM, CloudWatch. Xây dựng Docker multi-stage cho Fargate. -
\textbf{Giai đoạn 2 - Phát triển cục bộ (Tuần 3-4)}: Docker Compose với
PostgreSQL, Qdrant, Kafka. Phát triển Scrapy SitemapSpider, Kafka
Consumer, ETL pipeline với Star Schema, SentenceTransformer
vectorization. - \textbf{Giai đoạn 3 - Production AWS (Tuần 5-6)}:
Deploy Fargate crawler với EventBridge scheduler, Lambda Consumer với
SQS trigger, Lambda ETL với Bedrock Titan Embed v2, Lambda RAG API với
API Gateway, Next.js frontend. - \textbf{Giai đoạn 4 - Kiểm thử (Tuần
7-8)}: RAGAS evaluation (Faithfulness, Relevancy, Precision, Recall),
CloudWatch dashboards và alerts, Locust load testing, tối ưu chi phí.

\hypertarget{yuxeau-cux1ea7u-kux1ef9-thuux1eadt}{%
\paragraph{Yêu cầu kỹ thuật}}

\begin{itemize}
\tightlist
\item
  \textbf{Data Pipeline}: Scrapy với SitemapSpider, Kafka (local) / SQS
  (AWS), PostgreSQL với pgvector.
\item
  \textbf{ETL Pipeline}: Làm sạch HTML bằng regex, chunk text 500
  tokens, embedding qua SentenceTransformer (local) / Bedrock Titan v2
  (AWS).
\item
  \textbf{RAG System}: pgvector HNSW similarity search (cosine
  distance), Groq API (Qwen3-8B, Llama 3.1), Gemini 2.0 Flash fallback,
  structured prompts với trích dẫn nguồn.
\item
  \textbf{Infrastructure}: Terraform cho AWS resources, Docker
  multi-stage builds, Lambda deployment packages, EventBridge cron
  scheduling.
\end{itemize}

\hypertarget{ux111uxe1nh-giuxe1-rux1ee7i-ro}{%
\subsubsection{7. Đánh giá rủi
ro}}

\hypertarget{ma-trux1eadn-rux1ee7i-ro}{%
\paragraph{Ma trận rủi ro}}

\begin{itemize}
\tightlist
\item
  Crawler bị chặn: Medium impact, medium probability (giảm thiểu với
  headers phù hợp, tôn trọng robots.txt, DOWNLOAD\_DELAY).
\item
  Bedrock throttling: Medium impact, low probability (giảm thiểu với
  retry logic, adaptive backoff).
\item
  LLM API outage (Groq/Gemini): High impact, low probability (giảm thiểu
  với multi-model fallback).
\item
  Vượt chi phí: Medium impact, low probability (giảm thiểu với budget
  alerts, right-sizing).
\end{itemize}

\hypertarget{chiux1ebfn-lux1b0ux1ee3c-giux1ea3m-thiux1ec3u}{%
\paragraph{Chiến lược giảm
thiểu}}

\begin{itemize}
\tightlist
\item
  \textbf{Crawler}: Tôn trọng robots.txt, 1s DOWNLOAD\_DELAY,
  AutoThrottle bật.
\item
  \textbf{Throttling}: Exponential backoff trên Bedrock,
  max\_attempts=3.
\item
  \textbf{LLM Fallback}: Chuỗi fallback: Groq Qwen3 \(\rightarrow\)
  Llama 3.1 \(\rightarrow\) Gemini 2.0 Flash.
\item
  \textbf{Chi phí}: AWS Budget alerts tại 80\%, Fargate Spot cho
  crawler, right-size Lambda memory.
\end{itemize}

\hypertarget{kux1ebf-houx1ea1ch-dux1ef1-phuxf2ng}{%
\paragraph{Kế hoạch dự
phòng}}

\begin{itemize}
\tightlist
\item
  Nếu site báo chặn crawler: Dùng nguồn tin thay thế hoặc upload dữ liệu
  thủ công.
\item
  Nếu Bedrock không available: Dùng SentenceTransformer local.
\item
  Nếu chi phí vượt ngân sách: Giảm Aurora xuống 1 ACU.
\end{itemize}

\hypertarget{kux1ebft-quux1ea3-mong-ux111ux1ee3i}{%
\subsubsection{8. Kết quả mong
đợi}}

\hypertarget{cux1ea3i-thiux1ec7n-kux1ef9-thuux1eadt}{%
\paragraph{Cải thiện kỹ
thuật:}}

Tổng hợp tin tức tự động thay thế tìm kiếm thủ công. Hỏi đáp AI có trích
dẫn nguồn tiết kiệm thời gian. Kiến trúc serverless co giãn xử lý khối
lượng tin tức tăng dần.

\hypertarget{giuxe1-trux1ecb-duxe0i-hux1ea1n}{%
\paragraph{Giá trị dài hạn}}

\begin{itemize}
\tightlist
\item
  Hệ thống RAG nền tảng cho các dự án NLP/AI trong tương lai.
\item
  Các thành phần pipeline có thể tái sử dụng cho lĩnh vực khác (tech
  blogs, research papers).
\item
  Kinh nghiệm thực tế với AWS serverless.
\item
  Nền tảng dữ liệu (\textasciitilde5000 bài viết) cho phân tích sau này.
\end{itemize}
