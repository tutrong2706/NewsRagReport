\hypertarget{infrastructure-as-code-terraform}{%
\section{Infrastructure as Code
(Terraform)}}

This section covers the complete AWS infrastructure defined in
\texttt{main.tf} using Terraform for the News RAG Pipeline.

\hypertarget{architecture-overview}{%
\subsection{Architecture Overview}}

The Terraform configuration provisions:

\begin{itemize}
\tightlist
\item
  \textbf{VPC \& Networking}: Custom VPC, public subnets in 2 AZs,
  Internet Gateway, Route Tables
\item
  \textbf{Security}: Security Groups for ECS tasks and RDS, IAM Roles
  for ECS execution and tasks
\item
  \textbf{Database}: Aurora Serverless v2 PostgreSQL with pgvector
  extension
\item
  \textbf{Container Registry}: ECR repository for Docker images
\item
  \textbf{Container Orchestration}: ECS Cluster with Fargate task
  definitions
\item
  \textbf{Scheduling}: EventBridge Scheduler rules for daily pipeline
  execution
\item
  \textbf{Observability}: CloudWatch Log Groups
\end{itemize}

\subsection{VPC \& Networking
(main.tf:40-80)}}

\emph{(Mã nguồn chi tiết đã được lược bỏ để báo cáo ngắn gọn. Vui lòng

\textbf{Why public subnets?} Fargate tasks with
\texttt{assign\_public\_ip\ =\ true} need public subnets to: 1. Pull
Docker images from ECR 2. Call Bedrock, Groq, Gemini APIs 3. Reach SQS,
CloudWatch endpoints

\textbf{Key Design:} ECS tasks can reach Internet (for APIs, ECR). RDS
only accepts connections from ECS security group on port 5432.
