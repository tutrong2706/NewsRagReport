\paragraph{Data Normalization and Vector
Embedding}}

Raw data from the Crawler needs to be cleaned, chunked, and transformed
into vectors to support semantic search.

\textbf{1. Data Cleaning \& Star Schema}

Data is stripped of redundant HTML tags, date formats are normalized,
and stored in RDS Aurora PostgreSQL following the Star Schema model:

\begin{itemize}
\tightlist
\item
  \texttt{dim\_source}: Contains newspaper information
\item
  \texttt{dim\_time}: Detailed split of day/month/year
\item
  \texttt{dim\_author}: Manages normalized author information
\item
  \texttt{fact\_articles}: Central table containing articles
\item
  \texttt{fact\_chunks}: Contains text chunks split from articles
\end{itemize}

\textbf{2. Chunking with Langchain}

Articles are split into chunks with a maximum length of 800 characters
and a 150-character overlap to preserve context between segments.

\textbf{3. Vector Embedding with Amazon Bedrock}

NewsRAG v2 uses Amazon Bedrock with the
\texttt{amazon.titan-embed-text-v2:0} model (1024 dimensions) to
generate vectors instead of hosting a local \texttt{BAAI/bge-m3} model
like in v1. This reduces container load and saves resources.

\textbf{4. Vector Database (Qdrant \& pgvector)}

Vectors are upserted into Qdrant Cloud or stored directly in Aurora via
the \texttt{pgvector} extension with HNSW (Hierarchical Navigable Small
World) index to ensure \texttt{Top-K} query speeds remain under 50ms
even with millions of vectors.
